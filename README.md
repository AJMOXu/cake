# 船務提醒 APK（ShipAlert）

用手機攝像頭拍電腦螢幕 → 定時 OCR 識別中文 → 命中關鍵字／船長時間停留時，用 **PushPlus** 推送到微信。

- 最低支援 **Android 5.0（API 21）**
- OCR 使用 Google ML Kit 中文模型，**模型打包在 APK 內、離線可用**，不需要雲端 OCR 費用
- 全部是 Java，無 Kotlin

---

## 一、功能

| 功能 | 說明 |
|---|---|
| 到港提醒 | 畫面出現「停泊」→ 推送「⚓ 船已到達【罗兹班岛】港口」。位置取自**右上角地圖的標題**（備援：「XXX据点所属」） |
| 停留提醒 | 每次截圖都和上一次的**地圖區畫面**比較（32×32 灰度指紋）。畫面基本沒變 = 船沒動。超過 N 分鐘推送「⏳ 船已在【罗兹班岛】停留了 25 分鐘」，之後每隔 M 分鐘重複提醒 |
| 離開提醒 | 停留提醒發出後，地圖畫面恢復變化 → 推送「⛵ 船已離開…共停留 X」 |
| 自訂關鍵字 | 可加任意規則，例如 `卡莫斯 => 卡莫斯出現了！` |
| 防誤報 | 連續 N 次識別到才推送、同一關鍵字有冷卻時間 |
| 異常報警 | 長時間識別不到文字（手機被碰歪、電腦休眠、遊戲斷線）→ 推送「⚠️ 畫面異常」；App 被切到後台超過 1 分鐘 → 推送「監控已中斷」 |
| 除錯工具 | 「識別一次」「查看上次識別畫面」（綠框＝識別到的文字，藍框＝地圖區，橙框＝關鍵字區）；主畫面即時顯示「差異」數值，方便調閾值 |

## 二、編譯 APK（兩種方法擇一）

### 方法 A：GitHub 雲端自動編譯（不用裝任何軟體，推薦）
1. 在 GitHub 新建一個倉庫，把本資料夾全部內容上傳（含 `.github` 資料夾）。
2. 打開倉庫的 **Actions** 分頁 → 選 **Build APK** → **Run workflow**（上傳後通常也會自動觸發）。
3. 大約 5 分鐘後，在該次運行頁面底部 **Artifacts** 下載 `ShipAlert-apk`，解壓得到 `app-debug.apk`，傳到手機安裝。

### 方法 B：Android Studio
1. 安裝 Android Studio（Hedgehog 2023.1 或更新版）。
2. `File → Open` 選本資料夾，等待 Gradle 同步完成（首次會下載依賴）。
   - 如提示缺少 Gradle Wrapper，按提示讓它自動生成即可。
   - 在中國大陸下載慢，可打開 `settings.gradle` 取消註解阿里雲鏡像。
3. `Build → Build Bundle(s)/APK(s) → Build APK(s)`，APK 在 `app/build/outputs/apk/debug/`。

## 三、使用步驟

1. **PushPlus**：首次打開 App 會彈出 token 輸入框（之後可按「PushPlus Token」按鈕修改）。token 在 https://www.pushplus.plus →「發送消息 → 一對一消息」頁面複製。保存後會自動發一條測試推送。
2. **拍攝方向**：按「橫/豎屏」選擇。橫屏、豎屏**各自保存一套框位**，互不影響。
   - 橫屏：電腦螢幕能佔滿畫面，字最大、識別最準（推薦）。
   - 豎屏：手機直立更好擺放，但螢幕只佔畫面中間約 1/3，建議把解析度調到 2560×1440 或拉近變焦。
3. **擺放手機**：後攝像頭對準電腦螢幕，**插上充電器**。點預覽畫面可對焦，用「變焦」拉近。
4. **定位地圖**：按「**自動定位地圖**」——App 會找到「XX据点所属」字樣，自動算出右上角地圖的位置。
5. **微調框位**（可選）：按「**調整框位**」
   - 點框內 = 選中；按住框內拖 = 移動；拖白色圓點 = 縮放；在框外拖 = 重畫選中的框
   - 橙色「關鍵字區」框住畫面中間「停泊」出現的位置即可（避開左下角聊天欄可防誤報）
   - 長按「調整框位」可恢復預設
6. 按「**識別一次**」，看日誌中的位置、關鍵字是否正確。
7. 按「**開始監控**」。

> 框的作用：① 藍框告訴 App 去哪裡讀地名、比對「船有沒有動」；② 監控時 App **只識別兩個框覆蓋的範圍**，更快更省電，也不會被聊天文字誤觸發。
> 即使藍框偏了，App 也會在全畫面找「XX据点所属」作為位置備援。

> ⚠️ 監控時 **App 必須保持在前台、不要鎖屏**（App 已自動保持螢幕常亮）。

## 四、調參建議

| 設定 | 預設 | 說明 |
|---|---|---|
| 識別間隔 | 10 秒 | 老手機可改 15~30 秒，減少發熱 |
| 解析度 | 1920×1080 | 地名字太小識別不出 → 2560×1440 或拉近變焦；手機很卡 → 1280×720 |
| 連續識別次數 | 2 | 越大越不容易誤報，但提醒越慢 |
| 停留提醒時間 | 10 分鐘 | 超過就提醒一次 |
| 重複提醒間隔 | 30 分鐘 | 0＝只提醒一次 |
| 畫面差異閾值 | 8 | 看主畫面的「差異」數值：船靜止時的數值要**低於**它，航行時要**高於**它 |

關鍵字規則格式（設定 → 關鍵字規則）：
```
# 關鍵字1|關鍵字2 => 推送內容     {loc}=位置  {kw}=命中字  {time}=時間
停泊|停治 => ⚓ 船已到達【{loc}】港口，出現「停泊」提示（{time}）
卡莫斯 => 🐙 卡莫斯出現了！位置：{loc}
```
OCR 偶爾會把字認錯，如果發現常認成某個字，把它用 `|` 加進去即可。

**PushPlus 免費帳號每天約 200 條上限**，冷卻時間和重複間隔不要設太短。

## 五、專案結構

```
app/src/main/java/com/shipalert/
├─ MainActivity.java       攝像頭(CameraX) + OCR(ML Kit) + 介面
├─ SettingsActivity.java   設定頁
├─ RoiOverlayView.java     預覽上的框選疊加層
├─ PushPlusClient.java     PushPlus 推送（HTTPS 失敗自動改 HTTP，照顧老手機）
├─ AppConfig.java          讀取設定
└─ core/                   純 Java 邏輯（可單元測試）
   ├─ ScreenParser.java    位置提取、關鍵字匹配
   ├─ ShipMonitor.java     狀態機：到港 / 停留 / 離開 / 異常
   ├─ Signature.java       畫面指紋對比
   └─ KeywordRule.java …
app/src/test/…/ShipMonitorTest.java   以附件截圖模擬的測試
```

## 六、更好的替代方案（建議）

攝像頭拍螢幕會受反光、摩爾紋、對焦、手機被碰歪影響。如果**遊戲電腦可以裝程式**，更穩定的做法是在電腦上跑一個小腳本（Python），**直接截圖**再做同樣的 OCR＋對比＋PushPlus 推送：識別準確率接近 100%，也不佔用手機。需要的話可以再做一個電腦版。
